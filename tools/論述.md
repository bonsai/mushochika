# 論述の技術

## 目的

この文書では、無尽知化を説明するためのコードではなく、読者を納得させるための論述構造を定義する。

## 1. 論述の基本順序

```text
背景 → 事実 → 変化 → 問題 → 分解 → 仮説 → 提案 → 検証
```

今回の主題では、次のように展開する。

```text
AI技術の進歩
  ↓
仕事を構成する活動が変化する
  ↓
仕事の構造が変化する
  ↓
必要なSkillが変化する
  ↓
従来の職種定義だけでは説明しにくくなる
  ↓
仕事を構成要素へ分解する必要が生じる
  ↓
Ontologyが必要になる
  ↓
Intent → Agent → Workflowへ接続できる
  ↓
Vibe Codingによって実装できる
  ↓
Evidenceによって能力と成果を検証できる
  ↓
求人・採用・教育・評価・キャリアが変わる
```

## 2. 主張・根拠・解釈を分ける

数字や調査結果を、そのまま結論に接続しない。

```text
事実
 ↓
その事実が何を意味するか
 ↓
そこから生じる問題
 ↓
必要となる考え方
```

例えば「AIによって仕事がなくなる」と短絡せず、

> AIによって仕事を構成する活動の一部が自動化可能になる。
>
> したがって、仕事を職種という大きな単位だけで捉えるのではなく、活動・Skill・Knowledge・Toolなどへ分解する必要がある。
>
> その構造を機械と人間の双方が扱える形で定義するためにOntologyが必要になる。

というように、一段ずつ論理を進める。

## 3. 数字の使い方

数字は「権威付け」ではなく、論点を発生させるために使う。

```text
数字
 ↓
数字が示す意味
 ↓
既存の前提への影響
 ↓
新しい問題設定
```

例えば自動化可能性の推計を示す場合、

> 自動化可能性の割合は、その割合の仕事が消滅することを意味しない。むしろ、仕事を構成する活動が再編される可能性を示す。

と解釈を明示する。

## 4. 反論を先回りする

強い論述では、読者が持つ反論を先に提示して処理する。

### Vibe Coding

> Vibe Codingは単なるAIによるコード生成ではないのか？

これに対して、コード生成だけでは開発プロセスは完結しないと論じる。

```text
生成 → 実行 → テスト → 失敗 → 修正 → 検証 → Commit → Push
```

したがってVibe Codingは、AIとの対話を含む実装・検証ループとして捉える。

### Agent

> Agentは単なるLLMではないのか？

Agentは、目的・役割・能力・Tool・Workflow・状態・Evidenceを伴う実行主体として区別する。

### Ontology

> Ontologyは単なる分類表ではないのか？

Ontologyは分類だけではなく、概念と概念の関係、制約、意味を定義する。したがって、IntentやAgent、Workflowを接続する意味基盤として扱う。

## 5. 三段論法

中心命題は三段論法で構成する。

### 大前提

AIによって仕事を構成する活動が変化する。

### 小前提

AIに仕事を委ねるには、仕事の目的・対象・制約・能力・道具・成果を明示する必要がある。

### 結論

したがってAI時代には、仕事そのものをOntologyとして記述し、Intent・Agent・Workflow・Evidenceへ接続する新しい職能が必要になる。

## 6. 概念を混同しない

論述上、次の役割を明確に分離する。

| 概念 | 役割 |
|---|---|
| Ontology | 意味を定義する |
| Intent | 何を達成したいかを表現する |
| Agent | 意思決定・実行を担う |
| Tool | 能力を提供する |
| Workflow | 実行手順を構成する |
| Vibe Coding | AIとともに実装・検証する方法 |
| Evidence | 能力・実行・成果を検証する根拠 |
| Outcome | 実際に得られた結果 |

特に、Ontology・Agent・Tool・Workflowを同じものとして扱わない。

## 7. 論述の中心命題

```text
Ontology
 ↓
Intent
 ↓
Agent
 ↓
Tool
 ↓
Workflow
 ↓
Vibe Coding
 ↓
Repository
 ↓
Evidence
 ↓
Outcome
```

この流れを、単なる技術スタックではなく「仕事を意味から成果まで接続する構造」として説明する。

中心命題は次のように表現する。

> 仕事をOntologyとして定義し、Intentとして表現し、Agentとして実行し、Vibe Codingによって実装し、Evidenceによって能力と成果を証明する。

## 8. 求人・人材評価への接続

従来型の評価は、経験年数・職種・使用言語・資格などを入口にする。

これを、実際に何を考え、何を作り、何を実行し、何を達成したかというEvidence中心の評価へ接続する。

```text
Problem
 ↓
Issue
 ↓
Ontology / Schema
 ↓
Repository
 ↓
Commit
 ↓
Agent
 ↓
Workflow
 ↓
Test
 ↓
Evidence
 ↓
Outcome
```

ここで重要なのは、経歴を否定することではなく、経歴に加えて「実際に仕事を構造化し、実行し、成果を残した証拠」を評価可能にすることである。

## 9. 最終的な論理展開

```text
AIの進歩
 ↓
仕事の活動が変わる
 ↓
仕事の構造が変わる
 ↓
Skillの構造が変わる
 ↓
職種の定義が変わる
 ↓
求人の定義が変わる
 ↓
人材評価が変わる
 ↓
教育・キャリア設計が変わる
```

その変化を記述・実行可能にするために、

```text
Ontology → Intent → Agent → Workflow → Evidence
```

という構造を導入する。

## 10. 論述上の基本原則

1. **事実と解釈を分ける。**
2. **数字から結論へ飛躍しない。**
3. **主張には根拠を置く。**
4. **根拠には「何を意味するか」を添える。**
5. **反論を先回りする。**
6. **概念の境界を明確にする。**
7. **抽象論から具体例へ降り、再び抽象化する。**
8. **技術の話を、仕事・組織・社会の変化へ接続する。**
9. **最後は最初の問題設定に戻る。**
10. **結論を先に決め、後から数字を集めるのではなく、問い→証拠→解釈→結論の順に組み立てる。**

## 11. 無尽知化への接続

論述の最終到達点は、AIツールの紹介ではない。

```text
仕事
 ↓
知識
 ↓
意味
 ↓
Ontology
 ↓
Agent
 ↓
実行
 ↓
Evidence
 ↓
Knowledge
```

つまり、仕事を実行するだけでなく、実行によって得られたEvidenceを再びKnowledgeへ戻し、次の仕事の設計へ利用できる循環を作る。

この循環を「無尽知化」の基本論理として扱う。
